# Домовленості сервера server/

Як загальні скіли плагіна `engineering-paved-path` (`fastify-best-practices`,
`drizzle-orm-patterns`, `postgresql-table-design`) застосовуються саме тут; де вони розходяться,
діє цей файл. Головні правила модуля — у [../CLAUDE.md](../CLAUDE.md), таблиці й маршрути — у
[плані](../../docs/plans/web-rewrite-plan.md) §5, спільне (Zod, безпека) —
[../../docs/conventions.md](../../docs/conventions.md). Перенесено з розділів «In this project»
колишніх локальних скілів (2026-10-21; рішення IDEA-005 і IDEA-006 від 2026-10-09).

## Fastify

- Перша робота сервера — **журнал запитів**: застосунок і розширення роблять запити до e-Consul
  самі, а потім *звітують* про кожен у `POST /api/request-log`. Сервер також віддає сторінку,
  `locations.json`, журнал змін розкладу (`logs/schedule-changes.jsonl`), журнал резервувань і події
  розширення. Записи — назавжди.
- **Розширення теж пише** (`source: 'extension'` у журналі запитів, події в
  `/api/extension-events`): перевіряти так само, як дані застосунку; полю не довіряти через те, що
  воно від розширення.
- Ліміт тіла ~256 КБ, пачка — щонайбільше 100 записів. Маршрут запису валідує й вставляє одним
  запитом і відповідає 204: жодних читань чи збагачення на шляху запису.
- Модуль: `routes.ts` (zod-схеми, один виклик) → `service.ts` лише тоді, коли є логіка →
  `repository.ts` (Drizzle) — `onion-architecture` §11. Розширення (чистий JS) перевіряється тими
  самими схемами з `src/contracts/`.

## Drizzle

- Drizzle — лише в `src/modules/<m>/repository.ts` і `src/db/**`.
- Пачку вставляти одним `insert(...).values(rows).onConflictDoNothing({ target: <table>.clientId })`:
  застосунок повторює невдалі пачки, і повтор не має дублювати рядки.
- Репозиторій повертає типи контракту (`RequestLogEntry` тощо), не рядки таблиці; `bigint`-ідентифікатори
  й `timestamptz` перетворюються там.
- Жодної колонки для токена, заголовків чи тіла відповіді. Нова колонка, що могла б таке тримати, —
  спершу перевірка скілом `security` і [../../docs/conventions.md](../../docs/conventions.md) › «Безпека».

## Postgres

Таблиці — журнали подій, лише додавання (`econsul_requests` першою; журнал резервувань, події
розширення, зміни розкладу — за тими самими правилами):

- **Обсяг малий**: один користувач, перевірка раз на 60–180 с плюс часті біля відкриття — 1–2 тис.
  рядків на день, менше мільйона на рік. Звичайні B-tree індекси; без партицій, BRIN, Timescale, доки
  вимір не покаже іншого.
- Ключ — `BIGINT GENERATED ALWAYS AS IDENTITY` (порядок і курсори) плюс `UUID client_id UNIQUE` для
  ідемпотентних повторів.
- Час — `timestamptz` (`started_at` — коли браузер надіслав запит, `received_at` — коли сервер
  зберіг). Ніколи `timestamp` без поясу: консульства в різних поясах.
- Закриті набори — enum (`request_outcome`, `check_kind`), відкриті — `text` (`method`: сайт додає
  методи без попередження).
- `filters` — `jsonb` (різні для різних методів); шукати за винесеною колонкою `institution_code`, а
  не всередині JSON.
- `NOT NULL` на всьому, що є завжди; `http_status` — `NULL` лише для мережевої помилки, і це тримає
  `CHECK ((outcome = 'network_error') = (http_status IS NULL))`.
- **Без строку зберігання**: рядки назавжди (IDEA-005). Без `DELETE`, без TTL; виправлення — нові
  рядки, не `UPDATE`.

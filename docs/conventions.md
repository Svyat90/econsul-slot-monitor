# Домовленості для коду кількох модулів

Що в цьому проєкті уточнює загальні скіли плагіна `engineering-paved-path` (`zod`, `security`).
Скіл дає загальні правила, цей файл — як вони застосовуються тут; де вони розходяться, діє цей
файл. Перенесено з розділів «In this project» колишніх локальних скілів (2026-10-21). Домовленості
окремих модулів — `web/docs/conventions.md`, `server/docs/conventions.md`.

## Zod

- **Zod 4** (`zod@^4`, імпорт з `"zod"`) і в `web/`, і в `server/`, та сама версія (рішення
  2026-10-09, `docs/plans/web-rewrite-plan.md` §11). Новий код — у стилі Zod 4:
  - формати рядків — на верхньому рівні: `z.email()`, `z.uuid()`, `z.iso.datetime({ offset: true })`,
    а не `z.string().email()`;
  - власні повідомлення — `{ error: '…' }`, не `{ message: '…' }`; `.flatten()` → `z.flattenError()` /
    `z.treeifyError()`;
  - строгі об'єкти — `z.strictObject({...})`: кожне тіло запиту `server/` строге, тож зайвий ключ
    `token` — 422, а не мовчки відкинутий.
- Час e-Consul має вигляд `2026-11-11T09:00:00.00-06:00`: розбирати `z.iso.datetime({ offset: true })`
  і **зберігати рядок** — алгоритм слотів читає час консульства, записаний у ньому
  ([booking.md](booking.md) §7). Ніколи не переводити в локальний пояс у `transform` схеми.
- Протокол застосунок ↔ розширення — `z.discriminatedUnion('type', …)` у
  `web/src/domain/contracts/extension-messages.ts`; схеми API сервера — канонічні в
  `server/src/contracts/` (`web/` імпортує їх через alias `@contracts`).

## Безпека

Локальний інструмент для одного користувача: застосунок і розширення «e-Consul Helper» діють від
імені справжньої сесії e-Consul. Загальні розділи OWASP стосуються невеликої серверної частини, а
головні ризики — ось ці:

| Що | Правило | Де |
|---|---|---|
| **JWT e-Consul** (заголовок `token`, `localStorage.token` на сайті) | Живе в пам'яті вкладки застосунку й у `chrome.storage.session` розширення. Йде **лише** на `https://my.e-consul.gov.ua`. Ніколи — на наш сервер, у журнали, `console`, тексти помилок, URL, JSONL, `localStorage` застосунку, знімки екрана чи коміти | `web/src/adapters/econsul-api`, `extension/econsul.js`, `extension/background.js` |
| **Повідомлення застосунок ↔ розширення** | `postMessage` з цільовим `window.location.origin`, ніколи `"*"`. Приймач перевіряє `event.source === window`, `event.origin`, поле `source` (`econsul-app` / `econsul-ext`) і розбирає схемою протоколу; невідомі типи відкидаються. Фон віддає токен лише вкладкам, чий `sender.url` має origin застосунку (не за ознакою «немає вкладки»: попап, відкритий вкладкою, її має) | `extension/app-bridge.js`, `extension/background.js`, `extension/plans/extension-plan.md` §8 |
| **Автобронювання** («Підтвердити» на кроці 4) | Лише з увімкненим налаштуванням; кожен шлях, що може його натиснути, перевіряє налаштування в момент натискання. «Підтверджую» й «Записатись в чергу очікування» — ніколи. Жодних викликів API бронювання чи `PUT /documents` з нашого коду | `extension/picker.js`, `extension/econsul.js` |
| **Дозволи розширення** | `host_permissions` — лише `e-consul.gov.ua`, `my.e-consul.gov.ua` і localhost застосунку. Новий дозвіл чи хост — з причиною в самій зміні. Content scripts не вставляють віддалений код і не роблять `eval` | `extension/manifest.json` |
| **Журнали на сервері** (`/api/request-log`, `/api/extension-events`, `/api/schedule-log`, `/api/reservation-log`) | Метод, фільтри, статус, тривалість, результат — ніколи токен, заголовки чи тіла відповідей. Схеми тіл `.strict()`; обмеження розміру тіла; JSON лише; файли — за фіксованим шляхом, без шляхів чи команд із тіла. Сервер слухає `127.0.0.1`, сторінка й API — з одного origin, CORS немає. Події розширення не несуть ні токена, ні даних заявника | `server/src/modules/*`, `web/src/adapters/request-log`, `extension/background.js` |
| **Сторонній код на сторінці** | Сторінка тримає токен, тож кожен зовнішній скрипт — потенційний крадій токена. Без аналітики, без CDN-скриптів без точної версії та SRI; шрифти — лише локальні | `web/index.html`, `slots.html` |
| **Частота запитів до e-Consul** | Не опускати нижню межу моніторингу (інтервал ≥ 10 с, розклад раз на 30 хв, часті перевірки лише у вікні відкриття, тиша ±15 с навколо відкриття). Часті запити ризикують сесією й акаунтом | `web/src/domain/monitoring` |
| **Тести** | Ніколи не перевіряти бронюванням справжнього слота чи чергою очікування; лише заглушки й повідомлення з `test: true` (`extension/plans/extension-plan.md` §12) | — |

Не стосується проєкту, доки не зміниться стек: облікові записи й паролі, MongoDB, розмежування
доступу між користувачами, завантаження файлів. Такі знахідки для цього застосунку не звітувати.

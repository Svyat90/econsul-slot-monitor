## 1. Мета

Скоротити час від появи вільного слота до бронювання до одного кліку людини:

- щоранку чернетка заявки вже готова (кроки 1–3 пройдені на сайті);
- застосунок отримує токен сесії сам, без копіювання;
- коли застосунок знаходить слот, розширення відкриває чернетку на кроці 4 і **вибирає** слот;
- людина натискає «Далі».

## 2. Ухвалені рішення

| Питання | Рішення |
|---|---|
| Хто вибирає слот | Розширення вибирає слот у календарі сайту. «Далі» натискає людина |
| Який слот | **Найраніший новий** слот із перевірки, у межах діапазону дат, якщо його задано |
| Діапазон дат | Додати в застосунок поля «не раніше» і «не пізніше». **Обидва необов'язкові**; порожні — без обмежень. Діапазон фільтрує і нотифікації, і вибір слота |
| Для кого запис | Лише «для себе» |
| Чернетка | Одразу **автозаповнення** кроків 1–3 розширенням через інтерфейс сайту |
| Коли створювати чернетку | Щодня о **8:45** за місцевим часом (змінюється в попапі) і ще раз, коли до видалення поточної лишається менше години або сайт її вже видалив |
| Сповіщення про вхід | Усі чотири: системна нотифікація з кнопкою «Увійти», значок на іконці, банер у застосунку, звук |
| Дії при слоті | Розширення само перемикає на вкладку чернетки, відкриває крок 4, вибирає слот і вмикає сигнал |
| Сигнал «слот вибрано» | Власний звук, відмінний від інших. Звучить **щонайменше 30 с** і далі до дії людини («Далі» чи «Вимкнути звук»), але не довше 2 хв |
| Сигнал «сесія скінчилась» | Новий звук **«розбите скло»** замість теперішньої сирени, щоб його було легко відрізнити |
| Після повторного входу | Моніторинг, зупинений через завершену сесію, **запускається сам**, щойно приходить новий токен |
| Де план | Цей файл |
| Дизайн | **A · Державний**: світлий, синій `#0057B8` для дій і вибраного слота. Макети й токени — [docs/design/extension](../design/extension/README.md) |

## 3. Чого розширення не робить

- **Не натискає** «Далі», «Підтверджую», «Записатись в чергу очікування». Бронювання починається
  лише з дії людини (`public-check-and-book-appointments` викликається після «Далі», розділ 14.1 booking.md).
- Не викликає API бронювання, не пише в документ задачі напряму (`PUT /documents`) і не обходить
  перевірки кроку 3. Усе, що змінює заявку, робиться кліками в інтерфейсі сайту (розділ 14.7 booking.md).
- Не моніторить слоти: це лишається в застосунку.
- Не зберігає токен на диск і не передає його нікуди, крім застосунку на `http://localhost:3000`.

## 4. Архітектура

Розширення Manifest V3, ставиться локально в режимі розробника з теки `extension/` репозиторію.

```
extension/
  manifest.json
  background.js        service worker: стан, вкладки, будильники, нотифікації
  econsul.js           content script на https://e-consul.gov.ua/*
  app-bridge.js        content script на http://localhost:3000/*
  offscreen.html/.js   відтворення звуків без фокуса на сторінці
  popup.html/.js       статус і налаштування
  sounds.js            спільні генератори звуків (Web Audio), ті самі, що в slots.html
  icons/
```

```
 ┌──────────────────────┐   postMessage   ┌──────────────┐   runtime    ┌───────────────┐
 │ slots.html           │ ◄─────────────► │ app-bridge.js │ ◄──────────► │ background.js │
 │ (localhost:3000)     │                 └──────────────┘   messages    │ service worker│
 │ моніторинг слотів    │                                                └──────┬────────┘
 └──────────────────────┘                                                       │ runtime
                                                       ┌────────────────────────┼─────────────┐
                                                       ▼                        ▼             ▼
                                              ┌─────────────────┐     ┌──────────────┐  ┌──────────┐
                                              │ econsul.js      │     │ offscreen    │  │ popup    │
                                              │ робоча вкладка  │     │ (звуки)      │  │          │
                                              │ e-consul.gov.ua │     └──────────────┘  └──────────┘
                                              └─────────────────┘
```

### Компоненти

**`background.js` (service worker).**
- Стан у `chrome.storage.session` (пам'ять, не диск): токен, `exp`, статус входу, чернетка.
  Налаштування (час ранкової чернетки, установа/послуга, діапазон дат) — у `chrome.storage.local`.
- Будильники `chrome.alarms`: щоденна чернетка о 8:45, перевірка терміну чернетки, перевірка входу.
  Service worker засинає, тому все, що має статися пізніше, — лише через `chrome.alarms`.
- Керує **робочою вкладкою**: одна закріплена вкладка e-consul, яку розширення відкриває саме, якщо її
  немає. У ній читається токен, створюється чернетка й робиться вибір слота.
- Системні нотифікації `chrome.notifications` і значок `chrome.action.setBadgeText`.

**`econsul.js` (content script на e-consul.gov.ua).**
- Читає `localStorage.token` (той самий origin, що й сторінка) під час завантаження, за подією `storage`
  і раз на хвилину (без мережі). Передає токен і `exp` у background.
- Перевірка сесії: `GET https://my.e-consul.gov.ua/auth/me` з заголовком `token` раз на 10–15 хв.
  Запит іде від імені сторінки (Origin `https://e-consul.gov.ua`), як і запити самого сайту.
- Автозаповнення кроків 1–3 і вибір слота на кроці 4 — кліками й введенням у DOM.
- Відстежує перехід між кроками (зміна адреси) і натискання «Далі» на кроці 4.

**`app-bridge.js` (content script на localhost:3000).**
- Міст між сторінкою застосунку і background: `window.postMessage` лише з `window.location.origin`
  і з полем `source: 'econsul-ext'`. Так не треба знати ID розширення.
- Застосунок дізнається, що розширення є, з повідомлення `ext:hello`.

**`offscreen.html` (offscreen document, причина `AUDIO_PLAYBACK`).**
- Відтворює звуки, навіть коли фокус на іншій вкладці і без кліку на сторінці.

**`popup.html`.**
- Статус входу і скільки лишилось токену; стан чернетки (посилання, створено, видалиться о…);
  час ранкової чернетки; кнопки «Створити чернетку зараз», «Відкрити чернетку», «Увійти»,
  «Вимкнути звук».

### Права в manifest

`storage`, `alarms`, `notifications`, `offscreen`, `tabs`, `scripting`;
`host_permissions`: `https://e-consul.gov.ua/*`, `https://my.e-consul.gov.ua/*`, `http://localhost:3000/*`.

## 5. Сценарії

### 5.1. Вхід і токен

1. Робоча вкладка e-consul відкрита → `econsul.js` бачить токен → background зберігає токен і `exp`
   → передає застосунку (`ext:token`). Поле JWT у застосунку заповнюється саме.
2. Немає токена, `exp` минув, `auth/me` повернув 401/403 або застосунок отримав 401/403 від API
   → статус «не увійшли»:
   - червоний значок `!` на іконці;
   - нотифікація «Увійдіть на e-consul» з кнопкою «Увійти» (відкриває робочу вкладку на сторінці входу);
   - банер у застосунку;
   - звук «розбите скло».
3. Людина входить → новий токен приходить у застосунок → якщо моніторинг зупинився через сесію,
   застосунок **сам запускає його знову** з тими самими установою, послугою й інтервалами і пише
   в журнал «Resumed after login». Якщо моніторинг зупинили кнопкою Stop, він не відновлюється.
4. За 30 хв до `exp` — попередження в попапі та банер у застосунку.

### 5.2. Чернетка

Тригери: будильник 8:45; до видалення поточної чернетки менше години; сайт її видалив
(`GET /tasks/{id}` → 404 або `deleted`); кнопка в попапі.

1. Якщо не увійшли — сценарій 5.1, після входу продовжити.
2. Якщо зараз іде вибір слота (5.3) — відкласти.
3. Робоча вкладка → `https://e-consul.gov.ua/tasks/create/161374/161374001`.
4. Крок 1 (дані заявника): заповнити, чого бракує, або прийняти дані з профілю (етап 0).
5. Крок 2: країна й установа з налаштувань застосунку (код установи → назва з `locations.json`).
6. Крок 3: послуга, «для себе». Дочекатися перевірок сайту («Зачекайте, будь ласка, відбувається перевірка»).
   Якщо сайт показав «Запис … наразі недоступний» або «Сервіс недоступний» — зупинитися, нотифікація.
7. Перейти на крок 4 і **нічого не вибирати**. Адреса `/tasks/{taskId}/dateAndTimeVisitInfo`.
8. `GET /tasks/{taskId}`: перевірити `unitId` установи й код послуги в документі, взяти `createdAt`.
9. Зберегти `{ url, taskId, createdAt, expiresAt = createdAt + 24 год }`, передати застосунку
   (`ext:draft` → поле **Draft link**).

Стару чернетку не видаляємо: сайт видаляє невідправлені чернетки сам через добу.

### 5.3. Знайдено слот

1. Застосунок знаходить нові слоти, відкидає ті, що поза діапазоном дат, і надсилає `app:slots`
   зі списком, від найранішого.
2. Background перевіряє: увійшли, чернетка чинна, вибір слота зараз не йде (інакше ігнорує, але
   застосунок однаково показує свою нотифікацію).
3. Фокус на вікно й робочу вкладку; перехід на крок 4 чернетки з перезавантаженням (свіжий календар).
4. `econsul.js`: дочекатися календаря, натиснути «Шукати» (якщо є, етап 0), перейти на тиждень і день
   першого слота зі списку, **клікнути слот**, перевірити, що він позначився вибраним.
5. Якщо слота вже немає — наступний зі списку; якщо жодного — найраніший вільний на календарі
   в межах діапазону. Банер пояснює, що змінилося.
6. Прокрутити до слота, підсвітити: товстий контур, пульсація. Банер угорі:
   «Вибрано 31.03.2027 о 09:50 — натисніть "Далі"» і кнопка «Вимкнути звук». Кнопку «Далі»
   підсвітити, **не натискаючи**.
7. Сигнал «слот вибрано» (розділ 6): мінімум 30 с, далі до натискання «Далі» / «Вимкнути звук»,
   максимум 2 хв.
8. Людина натискає «Далі» → звук вимикається → розширення переходить у стан «бронювання надіслано»
   і **призупиняє** нові вибори слотів і створення чернеток, поки людина не відновить їх у попапі
   (щоб не зачепити щойно створений запис перенесенням зі `status: 2`).

## 6. Звуки й сповіщення

Усі звуки синтезуються Web Audio, як і зараз у `slots.html`. Спільний код — `sounds.js`.

| Подія | Звук | Де звучить | Тривалість |
|---|---|---|---|
| Нові слоти (застосунок) | Як зараз: дзвіночок, три висхідні ноти | slots.html | ~3 с |
| **Слот вибрано, натисніть «Далі»** | Новий: швидкі подвійні «біпи» високого тону (наприклад 1568/2093 Гц), повтор щосекунди. Не схожий на дзвіночок і на скло | offscreen | ≥30 с, до дії, ≤2 хв |
| **Сесія скінчилась / не увійшли** | Новий: **«розбите скло»** — короткий спалах білого шуму з різким спадом і кілька високих «дзенькотів» (3–6 кГц) із випадковими затримками, двічі | slots.html, якщо відкрита; інакше offscreen | ~2–3 с |

Щоб звук не грав двічі, background вирішує, хто відтворює: якщо застосунок підключений, він;
інакше offscreen.

## 7. Зміни в застосунку (slots.html)

1. **Діапазон дат**: два необов'язкові поля «не раніше» / «не пізніше» в блоці Monitoring
   (зберігаються в `localStorage`). Фільтрують слоти для нотифікацій, журналу «new:» і `app:slots`.
   Під полями — скільки вільних слотів відкинуто фільтром.
2. **Розширення**: рядок статусу «Розширення: підключено / немає», статус входу, `exp` токена.
3. **Токен**: поле JWT заповнюється з `ext:token`; ручне введення лишається запасним варіантом.
   Якщо моніторинг зупинився через сесію (не кнопкою Stop), новий токен запускає його знову (5.1, п. 3).
4. **Draft link** заповнюється з `ext:draft`; підказка показує точний час видалення (з `createdAt`).
5. **Банер «Увійдіть на e-consul»** угорі сторінки.
6. **Звук «розбите скло»** замість теперішньої сирени для сесії.
7. При нових слотах — `app:slots` у розширення (якщо підключене), окрім уже наявних звуку й нотифікації.
8. Кнопка **Test** для нових звуків (поруч із наявними тестовими кнопками).

## 8. Протокол повідомлень

Усі повідомлення — `{ source: 'econsul-ext' | 'econsul-app', type, ...payload }`.

| Напрям | `type` | Дані |
|---|---|---|
| розширення → застосунок | `ext:hello` | версія розширення |
| розширення → застосунок | `ext:auth` | `{ loggedIn, exp, reason? }` |
| розширення → застосунок | `ext:token` | `{ token, exp }` |
| розширення → застосунок | `ext:draft` | `{ url, taskId, createdAt, expiresAt }` або `null` |
| розширення → застосунок | `ext:booking` | `{ state: 'selecting' \| 'selected' \| 'submitted' \| 'failed', slot?, message? }` |
| застосунок → розширення | `app:hello` | — |
| застосунок → розширення | `app:selection` | `{ institutionCode, institutionName, countryName, serviceCode, serviceName }` |
| застосунок → розширення | `app:auth-failed` | `{ status }` (401/403 від API) |
| застосунок → розширення | `app:slots` | `{ slots: [{ date, time, consulIpnHash }], range: { from?, to? } }` |

## 10. Що з'ясувати на етапі 0

1. Крок 1: чи підставляються дані заявника з профілю, які поля обов'язкові.
2. Крок 2: як влаштовані списки країни й установи (MUI Autocomplete?), як їх заповнити програмно,
   щоб спрацювали обробники сайту.
3. Крок 3: вибір послуги й «для себе»; які перевірки запускаються і як зрозуміти, що вони завершились.
4. Крок 4: структура календаря (тижні з лічильником, сітка дня); чи є кнопка «Шукати»; як виглядає
   вибраний слот; **чи клік по слоту робить запити** (очікуємо лише збереження `chosenSlots`
   через `PUT /documents`, без `public-check-and-book-appointments`). Якщо клік по слоту запускає
   бронювання — розширення лише підсвічує слот, а вибирає людина.
5. Чи повторює сайт перевірки кроку 3, коли відкривається збережена чернетка, і скільки це триває.
6. Відповідь `GET /tasks/{id}`: де лежать `unitId`, код послуги, `createdAt`, ознака видалення.
7. Кнопка «Далі» на кроці 4: як її знайти і як розширенню побачити, що людина її натиснула.

## 11. Ризики

| Ризик | Що робимо |
|---|---|
| Сайт змінить розмітку, і автозаповнення чи вибір слота зламаються | Селектори в одному місці; кожен крок перевіряє, що дійшов куди треба, і при збої — нотифікація «Не вдалося … — зробіть вручну» з відкритою вкладкою |
| Клік по слоту запускає запити бронювання | Перевірка на етапі 0; тоді — лише підсвічування |
| Перенесення наявного запису (`status: 2`) | Після «Далі» розширення призупиняється (5.3, п. 8) |
| Service worker засинає | Лише `chrome.alarms` і `chrome.storage`; жодних довгих таймерів у background |
| Робочу вкладку закрили | Background відкриває її знову, коли вона потрібна |
| Mac засинає / вкладку пригальмовує Chrome | Як і для моніторингу: `caffeinate`, закріплена вкладка (booking.md, розділ 12) |
| Сесія скінчилась у момент вибору слота | Сценарій 5.1; після входу — повторити 5.3, якщо слот ще вільний |
| Увімкнуть капчу на бронюванні | Розширення її не чіпає: її розв'язує людина після «Далі» |

## 12. Як тестувати, нічого не забронювавши

- Етапи 1–2: вийти з e-consul / зіпсувати токен і перевірити сповіщення; кнопки Test для звуків.
- Етап 3: створити чернетку і перевірити `GET /tasks/{id}`. Чернетки сайт видалить сам.
- Етап 4: у застосунку тестова кнопка, що надсилає `app:slots` з **уже вільним** слотом із поточного
  календаря. Розширення відкриває чернетку й вибирає слот. **«Далі» не натискати**; після тесту
  закрити вкладку — чернетка лишається невідправленою.
- У тестовому режимі банер і попап показують «ТЕСТ», щоб випадково не натиснути «Далі».

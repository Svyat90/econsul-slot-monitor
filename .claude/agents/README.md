# Агенти

Агенти для виконання планів. Як вони вписуються в план —
[docs/plans/README.md](../../docs/plans/README.md) › «Як план виконується»; формат задачі — там само.

| Агент | Модель | Що робить | Пише | Скільки разом |
|---|---|---|---|---|
| [implementer](implementer.md) | sonnet | Одна задача плану (`S3.T1`, `F1.2`) у `web/`, `server/` або `extension/`: спершу тест, потім код, перевірка модуля | лише файли своєї задачі; не комітить | багато паралельно, файли не перетинаються |
| [plan-verifier](plan-verifier.md) | sonnet | Чи зроблено все, що обіцяє етап і його задачі; що зроблено зайвого | нічого | один, після останньої хвилі етапу |
| [architecture-reviewer](architecture-reviewer.md) | sonnet | Кільця, межі, шлях токена, контракти між застосунком, розширенням і сервером | нічого | один, паралельно з plan-verifier |

Порядок: задачі етапу в плані → `implementer` × N (по хвилях) → коміт кожної задачі основною
сесією → `plan-verifier` ∥ `architecture-reviewer` → задачі виправлення `F<раунд>.<n>` → повтор
перевірок лише для них.

Окремого агента-планувальника немає: задачі етапу пише основна сесія. Окремих скриптів перевірки
теж немає — їх замінюють команди модулів (`typecheck`, `vitest`, `arch:check`) і таблиця сигналів
в `architecture-reviewer`.

Спільні заборони для всіх: жодних запитів до e-consul.gov.ua, нічого не бронювати, токен нікуди
не потрапляє, без `pnpm install`, `docker`, міграцій і запуску серверів.

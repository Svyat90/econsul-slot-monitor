# Домовленості застосунку web/

Як загальні скіли плагіна `engineering-paved-path` (`react-best-practices`,
`frontend-ui-architecture`) застосовуються саме тут; де вони розходяться, діє цей файл. Кільця й
залежності — локальний скіл `onion-architecture`. Спільне з іншими модулями (Zod, безпека) —
[../../docs/conventions.md](../../docs/conventions.md). Перенесено з розділів «In this project»
колишніх локальних скілів (2026-10-21).

## Що визначає розкладку

- **Vite + React + TypeScript**, SPA з роутером (IDEA-006 у `docs/brainstorm/ideas.md`). **Next.js
  немає**: розділи скілів про App Router, `'use client'`, RSC і скіл `next-best-practices` тут не
  застосовуються — хіба як загальні ідеї розміщення.
- Fastify (`server/`) віддає зібраний застосунок і API `/api/*`. У розробці Vite пересилає `/api` на
  Fastify. Застосунок говорить із сервером лише через адаптер над `/api`.
- **e-Consul викликається з браузера** з токеном користувача (Cloudflare блокує запити з сервера);
  моніторинг іде у відкритій вкладці; розширення говорить зі сторінкою через `postMessage`.
- Маршрути `/slots`, `/monitoring`, `/settings` під одним макетом із бічним меню (блок стану,
  навігація) і глобальними банерами (сесія, нові слоти) — [дизайн](design/README.md).
- **Перший рівень більший, ніж зазвичай, і живе поза features.** Алгоритм слотів, правило горизонту
  й розклад моніторингу — чистий домен у `src/domain/`; введення-виведення — за портами в
  `src/application/` і `src/adapters/`. Ці кільця — справа `onion-architecture`; `frontend-ui-architecture`
  відповідає за `src/app/` і `src/features/` і за те, як вони їх споживають.
- Features: `locations` (країна, установа, послуга), `slots` (календар, панель дня, наступне
  відкриття, найближчий вільний), `monitoring` (зведення дня, журнал перевірок із фільтрами,
  журнал резервувань, зміни розкладу), `settings` (пошук, сесія, перевірки, бронювання, сповіщення),
  `status` (блок у бічному меню), `extension` (стан зв'язку, автобронювання).
- Тексти інтерфейсу — українською; вигляд — дизайн A розширення (Manrope, IBM Plex Mono для часу,
  `#0057B8`). Шрифти лише локальні (`@fontsource/*` чи `web/public/fonts`), ніколи Google Fonts —
  сторінка тримає токен.

## Дані й ефекти

- **Дані e-Consul належать сховищу моніторингу** (`src/application/monitor.ts`); компоненти читають
  їх через `useSyncExternalStore` у хуку (`useMonitor`). Ніколи не викликати `fetch` чи адаптер
  e-Consul з компонента чи `useEffect`. Дані сервера з `/api` (історія журналів, зведення дня)
  можуть іти через TanStack Query; ні те, ні інше не копіювати в другий кеш.
- **Замість `useApiQuery` / Axios зі скіла:** один HTTP-клієнт на зовнішній API (тут —
  `src/adapters/econsul-api`), він володіє базовим URL, заголовками й перетворенням помилок
  (401/403 → `SessionExpiredError`); компоненти запитів не будують.
- **Таймери й зовнішні події.** Довгі цикли (моніторинг, опитування, зворотний відлік) живуть поза
  React у сховищі; компоненти підписуються. Цикл у `useEffect` подвоюється в Strict Mode і
  перезапускається зі зміною залежностей. `window.addEventListener('message', …)`, `Notification`,
  Web Audio — адаптери, підключені один раз у composition root, не в компонентах. Текст відліку
  («наступна перевірка за 42 с») може тікати в компоненті; рішення, *коли* перевіряти, — ні.

## Де лежать константи

| Що | Де |
|---|---|
| межі вікна частих перевірок, тиша навколо відкриття, типові 60–180 с | `src/domain/monitoring/schedule.ts` |
| ключі `localStorage` | усередині `src/adapters/settings-store/` |
| базовий URL e-Consul, методи `external_reader` | усередині `src/adapters/econsul-api/` |
| частоти звуків | усередині `src/adapters/alerts/` |
| рядки `type` повідомлень | `src/domain/contracts/extension-messages.ts` |
| тексти інтерфейсу | компонент, що їх показує |
